# Independent role: methodology reviewer

Act as a hostile ACL methods reviewer. Check annotation target, intervention realism, consistency, observational vs causal claims, cherry-picked examples, gold-label dependence on context, contamination, target-only structural limitation, imbalance, sampling plan, template artifacts, and dataset unit mismatch. Attempt to find examples where the intended label reversal is not human defensible. Suggest concrete falsification controls. Verdict with critical/major/minor blockers and evidence.

## Independent methodology review, 2026-11-12

**Verdict: REVISE.** The prefix-label mismatch and the absence of a verified, authorized split manifest block an interpretable real-data evaluation. The controls below are review findings for later protocol revision. This review used repository instructions, the public CompanionHarm README, and public papers. It did not open source dialogues, inspect held-out rows or predictions, or run inference.

### Critical blockers

- **Align the anchor and edit gold labels with the detector's evidence window.** CompanionHarm's Data Annotation section says reviewers used the complete conversation when labeling each AI utterance. Its Experimental Setup gives the detector only preceding turns. Subsequent user reactions, disambiguation, or a later boundary clarification may change the full-history judgment. A prefix-conditioned evaluation needs the same prefix-plus-marked-target view and rubric for fresh blind judgments of all arms, including the original. Keep the original full-conversation votes for provenance, sampling, and a prespecified disagreement analysis. Log the upstream gold mismatch explicitly in baseline replication. [CompanionHarm, Data Annotation and Experimental Setup](https://arxiv.org/html/2608.25377)
- **Separate independent label judgment from edit validation.** The protocol mentions both arm blindness and rating edit intent. Use independent single-arm raters with at most one arm of a source conversation per rater, identical visible fields and formatting, randomized assignment, and calibration material outside the held-out set. Editors, evaluators, and arm-label raters should have distinct responsibilities. Collect harm status, optional taxonomy category, confidence, evidence turns, coherence, and an insufficient-evidence or ambiguous outcome. Lock arm judgments before a separate quality reviewer sees the pair to check realism, semantic scope, and alternative explanations. Predeclare adjudication and how to handle defensible disagreement. Independent arm gold determines the observed pair relation. Preserve separately the intended relation, the observed relation, and the pair-quality decision, including cases that miss intent. Pavlopoulos et al. §3.1 used mutually exclusive annotator groups for fixed-comment exposure to different context views. [Toxicity Detection: Does Context Really Matter?](https://aclanthology.org/2020.acl-main.396.pdf)
- **Demonstrate split isolation at the conversation and derivative level.** Verify the upstream grouped splits from a pinned, authorized copy. Record development exposure for any legacy model, saved run, public benchmark result, and threshold. Audit normalized copies and plausible near-duplicates within and across corpora. Keep variants, repeated targets within a source conversation, and duplicate conversation groups together. Define template families and a template-holdout diagnostic prospectively. Keep model and protocol developers blind to final test rows. If official test anchors are the prospective final evaluation source, use a separated approved custodian for split QA and apply frozen edit and selection rules after G4. Keep edit failures and all attrition. Material prior row exposure requires a separately locked evaluation cohort or explicitly exploratory interpretation. The README split counts are an upstream assertion pending file-level verification. [CompanionHarm README, Benchmark design](https://github.com/HanMeng2004/CompanionHarm#benchmark-design)
- **Verify that model inputs contain the intended evidence.** A matching target hash proves string identity. Separately check role order, prefix-only construction, exactly one marked target slot, and that truncation preserves the target in every arm. Verify context fields for future turns, serialized labels or votes, model outputs, and duplicated target occurrences. A genuine earlier repetition and a pipeline-added copy require different treatment. Log sanitized counts of evidence visibility and token lengths after rendering, including when a neutral addition accidentally pushes decisive evidence outside the model window. Use the same label space and threshold policy across conditions.

### Major revisions before a pilot decision

- **Challenge the construct at the item level.** In a synthetic boundary example, a user initially accepts a nickname and later withdraws consent. Adding prior acceptance while keeping the later withdrawal intact is unlikely to isolate a defensible reversal for a target that repeats the nickname. In a synthetic role-play example, a harmless fictional frame can coexist with a real explicit boundary the target ignores. An ostensibly irrelevant emotional aside may change whether the target disregards a support request. These are hypotheses for reviewers. Require candidates to have a coherent conversational history, a clearly identified target behavior and evidence, and an explicit account of other plausible cues. Keep an option for impossible edits. Some edits change harm type without changing binary harm status. Record such cases separately if category-level judgments are collected.
- **Test for evidence use beyond sensitivity.** Use matched preserve and change edits on the same axis where defensible. Match edit operation, role, turn position, length and surface cues where feasible. A context-only detector may find an elevated-risk conversation while ignoring whether the target endorses or resists the risk. Include a context-only diagnostic, edit-status or edit-family detection from surface features, role/order diagnostics, and a prespecified check of rater-identified evidence versus comparable distractors. Where the evidence check alters context, validate its semantics before scoring against gold and keep its estimand separate. Test exact replay to measure inference instability. A paired change identifies a response to the supplied inputs under the evaluation procedure. Evidence-span overlap supports a claim about localization. A model explanation by itself cannot establish that the cited span drove its decision.
- **Treat existing metrics and evidence localization as precedented.** ConCI §§4.2–4.3 and F generate hold/flip conditions on the same contextual-integrity axis and collect per-flow judgments, including author judgments. Its §§5.1–5.3 score joint pair correctness and report prediction agreement on hold pairs. The latter's complement is UFR, and flip-pair joint correctness has the CCAR form. CompanionSafe §§3.1.4, 3.2 and 5 and Appendix D already use judge evidence to localize offending assistant turns, compare detectors, and evaluate transfer to CompanionHarm and AICompanionBench. The defensible candidate is an independently validated **preceding relational evidence** audit of fixed companion responses, with paired controls that rule out plausible shortcuts. [ConCI](https://arxiv.org/pdf/2610.24494) · [CompanionSafe](https://arxiv.org/html/2610.18095)
- **Separate benchmark composition from population inference.** Predefine the eligible source population and a conversation-level probability sample separately from enriched strata based on class, original agreement, context length, or locked development-model error. Record inclusion probabilities where inference uses them, anchor availability, attempted versus unconstructible edits, rejections, gold disagreements, and exclusions by family and direction. Set rules for handling valid pairs whose observed relation misses the intended stratum before model results are available. Inspect label balance by direction and source stratum. A selected and validated benchmark estimates detector behavior on that mixture. The upstream Replika conversations were user-shared in a specific online setting, and neither a benchmark balance quota nor a sample drawn within that corpus estimates deployment prevalence. [CompanionHarm, Data Collection and Corpus Statistics](https://arxiv.org/html/2608.25377)
- **Use the target-only and constant models as structural controls.** A deterministic target-only predictor has UFR zero and CCAR zero when target model inputs are identical and the relevant gold is binary and changes. A constant classifier's joint accuracy depends on the preserving-pair label mix. Pair both primary rates with joint accuracy and label-stratified denominators. A substantive comparison uses a matched context-capable detector or a prespecified, length- and edit-matched control, with the same splits, tuning and threshold budget. Report target-only scores as structural checks alongside ordinary classification performance. Score altered contexts with unknown gold as perturbation diagnostics. No Convo! §§3.1, C independently validates sampled paraphrases by displaying the original, rewrite, and given label, a separate validation design from blinded prefix-only judgments in the present proposal. [No Convo!](https://aclanthology.org/2026.findings-aacl.204.pdf)
- **Keep external label units distinct.** AICompanionBench §§III–IV reports a conversation-level, LLM-screened corpus. A human annotator revisited initial labels using model outputs, including outputs from the family of models evaluated in the paper. This is a distinct sampling and labeling process. A rights-cleared evaluation could use a documented conversation-level task and crosswalk, with caveats about label generation and model-reference dependence. Utterance-level validation requires separately adjudicated utterance labels. [AICompanionBench](https://arxiv.org/html/2606.04867)

### Minor clarifications and go/no-go tests

- Distinguish a detected model input effect from a claim about human outcomes. A local fixed-target detector comparison measures changes to detector judgments. SIM-VAIL's intervention regenerates chatbot messages or rewrites a concerning target and evaluates subsequent responses, which answers a different question. [SIM-VAIL, Counterfactual interventions and Counterfactual branching analyses](https://www.nature.com/articles/s41591-026-04577-2)
- In the baseline audit, pin artifact and manuscript versions separately. The public README describes eight systems and archived predictions, while arXiv v1 describes seven models. Keep the protocol's A/B/C values explicitly unverified until a traceable run and label/threshold contract is supplied. [CompanionHarm README](https://github.com/HanMeng2004/CompanionHarm#benchmark-design) · [CompanionHarm arXiv v1](https://arxiv.org/html/2608.25377v1)
- A future synthetic-only check should reject a changed target, a leaked conversation group, a suffix in a prefix input, a dropped target under truncation, and an unknown relation counted as valid. Verify all pair metrics against deterministic constant and perfect predictions. Human study approval remains G2, and pilot validation and prespecified stopping criteria remain G3. No synthetic fixture can demonstrate construct validity for real dialogue.

## Independent implementation follow-up, 2026-11-12

**Verdict: development audit interpretable as exploratory; revise the human pilot specification before G2/G3.** I checked the selected research decision, implementation, and aggregate outputs, and ran four synthetic unit tests covering the blinded assignment and paired metrics. No dialogue files, models, or item-level outputs were accessed.

- **Experiment A measures two distinct contrasts.** The natural-input comparison uses separately trained target-only and full-prefix lexical models against inherited CompanionHarm binary labels. The context-removal probe instead runs the fixed full-prefix model on reduced inputs. Report both with their corresponding denominators. The development macro-F1 difference is 0.004 with a conversation bootstrap interval of approximately −0.030 to 0.038. It does not establish a gain. The alteration diagnostics compare predictions with the full-input model and their valid set is defined by an observed prefix and available probe. Keep the broad original-corpus labels separate from new pilot judgments. Record the existing transformer as a required comparison whose exact model artifact and input contract are pending. [Development aggregate](../results/CONTEXT_AUDIT_DEV.json) · [Runner](../scripts/run_context_audit.py)
- **Clarify what each unknown-label control manipulates.** `neutral_padding` replaces the prefix with repeated synthetic words of approximately matched whitespace length. It tests substitution with a fixed string. An added-distractor test should retain the observed prefix, insert the padding at a prespecified location, and check whether evidence and target remain visible. Keep both types as diagnostic unless independently adjudicated. The shuffle and depth rates include no-op rows, such as one-turn shuffles and prefixes already no longer than three turns. Report how many rendered inputs actually changed, preserve the original diagnostic denominator, and avoid interpreting a lower rate as proof of robustness. Mismatching may reuse donor contexts and drop role or turn structure. Its recipient bootstrap describes the fixed donor assignment. Do not extrapolate to arbitrary donor choices. [Runner](../scripts/run_context_audit.py)
- **The prepared queue and the five-family pilot have different scopes.** The aggregate verifies 50 development source IDs split across probability and enriched samples, with 100 potential edits and zero constructed edits or human ratings. The boundary-specific packet covers only one of the five requested families and uses a narrower outcome than focal harmfulness. Keep it as a specialized module. The main rubric needs explicit harmful, safe, undetermined and skip outcomes, and family-specific edit contracts for fiction framing, boundaries, vulnerability, distraction, and distance. Permit a documented insertion or relocation when its family requires it, with role and chronology checks appropriate to that operation. The current candidate validator checks target identity and equal role sequence, and therefore rejects valid candidates whose role sequence must change. Maintain aggregate attempt, failure, and accepted counts by family, relation, direction, and sampling stratum. Check whether multiple development IDs represent the same source conversation before assignment. [Pilot queue aggregate](../results/PILOT_QUEUE.json) · [Pilot packet](../protocols/BOUNDARY_PILOT_PACKET.md) · [Packet builder](../scripts/prepare_blind_pilot.py)
- **Preserve blindness through the complete annotation workflow.** Opaque IDs, randomized order, three assignments per arm and disjoint reviewer codes across a source's arms support the planned blindness. Before distributing packets, verify authorized redaction and access to each reviewer's view. Log edited turns and intended relation privately, then lock the single-arm ratings before a separate pair-quality review. Define the adjudication rules and record undetermined arms and intent mismatches. The current builder prepares assignments only. It has no judgment intake, adjudication or independent pair-quality output. The requested target-only reannotation should be a separately randomized subset with a disjoint reviewer pool for each source and an insufficient-evidence option. Its labels measure the effect of removing evidence from the human view and should stay separate from the paired prefix gold. [Pilot packet](../protocols/BOUNDARY_PILOT_PACKET.md) · [Packet builder](../scripts/prepare_blind_pilot.py)
- **Keep later decisions conditional.** The paired helper tests UFR, CCAR, joint accuracy and common bootstrap draws on synthetic labels. Use it after human adjudication and add direction, denominator, and edit-intent reporting for the frozen evaluation. Expansion from 50 to approximately 300 sources depends on independently validated pairs in both relations, feasibility and precision. AICompanionBench remains a separately governed conversation-level evaluation with frozen aggregation and overlap checks. Routing requires an informative result from B and a common cost policy that accounts for reviewer error. [Paired metrics](../scripts/paired_metrics.py) · [Gates](../protocols/GATES.md)
